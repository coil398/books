Chapter 02 · 形式手法とテスト技法

Lean 4 実践サンプル

数学・物理学・ゲーム・Webの中核性質を、型・定義・定理へ切り出します。

対象01章のLean基礎を終えた人
成果物ドメイン性質をLeanへ翻訳できる
読む目安70〜100分

この章で学ぶこと

  • 自然数・代数・順序を証明する
  • 単位・盤面・認可を型へ切り出す
  • Leanと実装の接続境界を説明する

前提知識

  • induction、simp、omega、ring
  • List・Bool・inductive
  • 基本的なドメイン設計

所要時間の目安

四領域から最低一例ずつ選び、保証の境界を書きます。

サンプルを実行する準備

この章の例は、数学・物理学・ゲーム・Webアプリケーションの性質をLeanで表します。保証したいこと、なぜ重要か、破れたときの影響を先に説明し、コードは一つの`Main.lean`へ貼れる形を目指します。

Shell
lake new lean-examples math
cd lean-examples
cp /path/to/Main.lean Main.lean
lake env lean Main.lean
lake build

一つのファイルへ多くの例を貼ると、定理名の衝突や型変数の推論差が出ます。まず一例ずつ`example`として動かし、意味が固まったらnamespaceとファイルを分けます。

コードが通ることと仕様が正しいことは別

Leanが検査するのは書かれた定義と定理です。物理法則の近似範囲、ゲームのルール、WebのミドルウェアやDB接続は別の境界として記録します。

数学：自然数とリスト

例1：加法の単位元

保証したいのは任意の自然数nについてn + 0 = nです。空のバッチを追加しても集計値が変わらないという、業務処理の基礎になります。破れると、初期化や空集合の扱いで数量がずれます。

Lean 4
import Mathlib

theorem nat_add_zero (n : Nat) : n + 0 = n := by
  induction n with
  | zero => rfl
  | succ n ih => simp [Nat.succ_add, ih]

例2：mapとappendの長さ保存

変換や分割が要素を落とさないことを保証します。ページネーションや固定長バッファの上限計算が壊れると、欠落・重複・バッチの取りこぼしが起きます。

Lean 4
import Mathlib

theorem map_length (f : α → β) (xs : List α) :
    (xs.map f).length = xs.length := by
  induction xs with
  | nil => rfl
  | cons x xs ih => simp [ih]

theorem append_length (xs ys : List α) :
    (xs ++ ys).length = xs.length + ys.length := by
  induction xs with
  | nil => simp
  | cons x xs ih => simp [ih]

例3：最大値の上限

Lean 4
import Mathlib

theorem max_le_of_le {a b c : Nat} (ha : a ≤ c) (hb : b ≤ c) :
    max a b ≤ c := by
  exact max_le ha hb

example (xs : List Nat) (h : ∀ x ∈ xs, x ≤ 100) :
    ∀ x ∈ xs, x ≤ 100 := by
  exact h

入力制約を前提として型に渡すと、後段で同じ制約を何度も再検査しなくて済みます。ただし、境界で本当に上限を検証したかはPBTやAPIテストで確認します。

数学：代数・順序・合同

例4：群の逆元

操作を巻き戻すと単位元に戻る性質を保証します。認証や暗号の数学的核を説明する例にはなりますが、暗号実装全体の安全性を証明するものではありません。

Lean 4
import Mathlib

variable {G : Type*} [Group G]

theorem inv_mul_cancel_custom (x : G) : x⁻¹ * x = 1 := by
  exact inv_mul_cancel x

theorem mul_inv_cancel_custom (x : G) : x * x⁻¹ = 1 := by
  exact mul_inv_cancel x

例5：順序の反射性・推移性

Lean 4
import Mathlib

theorem le_trans_custom {α : Type*} [Preorder α]
    {a b c : α} (hab : a ≤ b) (hbc : b ≤ c) : a ≤ c := by
  exact le_trans hab hbc

theorem le_refl_custom {α : Type*} [Preorder α] (a : α) : a ≤ a := by
  exact le_rfl

価格や権限レベルの比較が推移的であることを確認します。比較が推移的でないドメインにPreorderを付けると、証明の前提そのものが誤ります。

例6：剰余算術

Lean 4
import Mathlib

example : (17 : ZMod 5) = 2 := by
  decide

theorem congruence_add (a b : ZMod 7) : a + b = b + a := by
  exact add_comm a b

`ZMod n`は剰余を型に埋め込み、整数と剰余の混同を減らします。ハッシュや暗号の補助計算では、整数の範囲と剰余の意味を別の型として扱います。

物理学：単位を型に入れる

物理量を一つの`ℚ`に詰め込むと、距離と時間を足す誤りが型検査をすり抜けます。ここでは教育用の最小モデルとして、`Meter`と`Second`を別型にします。SI単位系全体や次元解析器の実装ではありません。

Lean 4
import Mathlib

structure Meter where
  value : ℚ
deriving DecidableEq

structure Second where
  value : ℚ
deriving DecidableEq

def Meter.add (a b : Meter) : Meter :=
  ⟨a.value + b.value⟩

def Meter.scale (k : ℚ) (a : Meter) : Meter :=
  ⟨k * a.value⟩

def velocity (d : Meter) (t : Second) (h : t.value ≠ 0) : ℚ :=
  d.value / t.value

example (d : Meter) : Meter.scale 1 d = d := by
  cases d
  simp [Meter.scale]

保証したいのは単位の取り違えが型として表面化することです。破れると、シミュレーションの時間刻みを距離として扱い、速度や位置が意味のない値になります。

例：等加速度の離散式

Lean 4
import Mathlib

def nextPosition (x v a dt : ℚ) : ℚ :=
  x + v * dt + (a * dt^2) / 2

theorem nextPosition_zero_dt (x v a : ℚ) :
    nextPosition x v a 0 = x := by
  simp [nextPosition]

theorem nextPosition_affine (x v a dt : ℚ) :
    nextPosition x v a dt - x =
      v * dt + (a * dt^2) / 2 := by
  ring

時間刻み0で位置が変わらないことは、積分器の境界条件です。破れると停止したシミュレーションでも状態が動きます。浮動小数・丸め・安定性はこの代数式の対象外なので、PBTで許容誤差を検査します。

例：エネルギー式の同値性

Lean 4
import Mathlib

def energy (m v g h : ℚ) : ℚ :=
  m * v^2 / 2 + m * g * h

theorem energy_swap (m v g h : ℚ) :
    energy m v g h = m * (v^2 / 2 + g * h) := by
  ring
式の同値性は物理法則そのものではない

保存を主張するには運動方程式、境界、初期条件、誤差モデルが必要です。Leanが示すのは、ここで定義した式の代数的同値性です。

ゲーム：勝敗とスコア

例1：勝敗判定の全域性

どんな整数の組でも勝ち・負け・引き分けのいずれかになることを保証します。全域性が破れると、UI、リプレイ、ランキングが未知の結果値で停止します。

Lean 4
import Mathlib

inductive Result where
  | win | lose | draw
deriving DecidableEq, Repr

def result (a b : Int) : Result :=
  if a > b then .win else if a < b then .lose else .draw

theorem result_cases (a b : Int) :
    result a b = .win ∨ result a b = .lose ∨ result a b = .draw := by
  unfold result
  split <;> simp_all

例2：スコアの単調性

ボーナスを増やしたのにスコアが下がらないことを保証します。ランキングの逆転や報酬の不正減算を、数学的なpropertyとして固定できます。

Lean 4
import Mathlib

def score (base bonus : Nat) : Nat := base + bonus

theorem score_mono_bonus (base b₁ b₂ : Nat) (h : b₁ ≤ b₂) :
    score base b₁ ≤ score base b₂ := by
  exact Nat.add_le_add_left h base

theorem score_zero (base : Nat) : score base 0 = base := by
  simp [score]

例3：盤面遷移の不変量

Lean 4
import Mathlib

structure Board where
  pieces : Fin 9 → Bool

def place (b : Board) (i : Fin 9) : Board :=
  { b with pieces := fun j => if j = i then true else b.pieces j }

theorem place_true (b : Board) (i : Fin 9) :
    (place b i).pieces i = true := by
  simp [place]

`Fin 9`は0〜8の範囲にあるインデックスです。無検証の整数を使うと盤外アクセスを別の層で処理する必要があります。型で合法手を表しても、手番や勝敗ルールは別の不変条件として追加します。

Web：認可とページネーション

例1：認可のdefault deny

公開したくないRoleとActionの組合せを明示的に拒否します。破れると、ゲストの削除やメンバーの管理操作が権限昇格として実行されます。

Lean 4
import Mathlib

inductive Role | guest | member | admin
deriving DecidableEq

inductive Action | read | write | delete
deriving DecidableEq

def allowed : Role → Action → Bool
  | .guest, .read => true
  | .member, .read => true
  | .member, .write => true
  | .admin, _ => true
  | _, _ => false

theorem guest_cannot_delete :
    allowed .guest .delete = false := by
  decide

theorem admin_can_delete :
    allowed .admin .delete = true := by
  decide

例2：ページサイズの上限

ページサイズが上限を越えず、サイズ0なら空になる性質を保証します。offsetの計算やページ間非重複は、別の前提を持つ独立した定理にします。

Lean 4
import Mathlib

def page (xs : List α) (size offset : Nat) : List α :=
  (xs.drop offset).take size

theorem page_empty_size (xs : List α) (offset : Nat) :
    page xs 0 offset = [] := by
  simp [page]

theorem page_length_le (xs : List α) (size offset : Nat) :
    (page xs size offset).length ≤ size := by
  exact List.length_take_le _ _

例3：セッション状態

Lean 4
import Mathlib

inductive SessionState
  | anonymous | authenticated | revoked
deriving DecidableEq

def canRefresh : SessionState → Bool
  | .authenticated => true
  | _ => false

theorem revoked_cannot_refresh :
    canRefresh .revoked = false := by
  decide

theorem auth_refresh :
    canRefresh .authenticated = true := by
  decide

JWTの署名、時計、鍵ローテーション、キャッシュの読み方はこの純粋関数の外側です。純粋な認可表を証明しただけで、すべてのHTTP経路がこの表を通るとは限りません。

証明の設計と限界

観察設計への問い次の一手
Boolで表した命題として証明する必要があるかPropやDecidableを検討
Natでunderflowした負の値は入力不正か状態かInt、Option、proof-carrying型
単位が値の名前だけ型で混同を禁止できるかMeter、Secondなどのnewtype
casesが増えた状態のenumを整理できるかinductiveと遷移関数
Web定理は通る全経路が同じ認可関数を使うかPBT・統合テスト・監査

証明が難しいとき、数学を難しくする前にAPIの不変条件を見直します。証明できないものを無理に一つのLean定義へ寄せず、TLA+の状態モデルやPBTの実装propertyへ渡す方が、保証の説明が正確になります。

実装境界の記録
Leanが保証:
  純粋関数、型、算術、帰納データ

Leanが未保証:
  DB、時計、ネットワーク、手書き移植

TLA+へ渡す:
  競合、所有権、保存、状態順序

PBTへ渡す:
  JSON、実装境界、丸め、外部fake
値の名前だけで単位を守らない

`distance : ℚ`と`time : ℚ`は、名前を間違えれば加算できます。単位の取り違えが高価なら、型・レビュー・PBTを重ねます。

動かす順序と演習

  1. importを通す。
  2. 定義を#checkする。
  3. 具体的なexampleをdecideやnorm_numで確認する。
  4. 一般化してtheoremにする。
  5. 一行だけ壊し、失敗位置を読む。
  6. 本番コードへ移植する場合は接続propertyを置く。

演習：ドメイン別に一つずつ書く

数学では「リストのreverseを二回すると元に戻る」、物理では「dt=0で位置が変わらない」、ゲームでは「合法なFinインデックスに置くと占有される」、Webでは「guestのdeleteを拒否する」を選びます。各例に、保証・重要性・破壊時の影響をコメントで残します。

提出物の型

証明:
実装側で同じ意味だと確認する方法:

定理の数ではなく、設計上の意思決定がコードに戻っているかを確認します。

まとめ

数学では帰納法と代数、物理では単位と保存量、ゲームでは全域性と不変量、Webでは認可と状態を扱いました。どの例も、型・述語・補題によって「正しそう」を前提付きの主張へ変えています。

Leanが扱わない外部依存を無理に隠さず、TLA+やPBTへ境界を渡します。次章では、時間・並行性・Safety・LivenessをTLA+で表します。

用語集

全域性
定義が入力の全ケースを処理し、未定義の結果を残さない性質。
不変量
操作や遷移の前後で保持される性質。
単位型
MeterやSecondのように、同じ基礎値でも意味を型で分ける設計。
default deny
許可を列挙し、それ以外を拒否する認可設計。
Fin n
0以上n未満のインデックスを表す型。
underflow
自然数などの下限を越えたときに、意図しない値へ折り返す問題。

理解度チェック

問1：単位をLeanの型で分けると、何が防げますか。
距離と時間のように、同じ基礎型の値を誤って加算する混同を型エラーにできます。
問2：`Fin 9`を盤面インデックスに使う理由は何ですか。
0〜8の範囲を型で保証し、盤外アクセスの前提を減らすためです。
問3：認可関数の定理が通っても、Web全体の認可が安全とは限らないのはなぜですか。
キャッシュ、ミドルウェア、別経路、JWTや時計など、関数の外側があるためです。
問4：物理式の代数的同値性と物理法則は何が違いますか。
前者は定義した式の変形、後者は運動方程式や境界条件を含むモデルだからです。
