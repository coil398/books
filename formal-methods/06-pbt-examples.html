Chapter 06 · 形式手法とテスト技法

PBT 実践サンプル

Web・数学・物理学・ゲームの実装を、往復性・モデル比較・誤差境界・状態機械で揺さぶります。

対象05章でgeneratorとshrinkを読んだ人
成果物領域固有のpropertyと境界値を設計できる
読む目安80〜110分

この章で学ぶこと

  • Webの入力・認可・時計を検査する
  • 数値と物理の誤差契約を書く
  • ゲームの状態・seed・バランスを検査する

前提知識

  • Hypothesisまたはfast-check
  • generator・shrink・stateful test
  • fake依存の注入

所要時間の目安

四領域から最低二例ずつ読み、失敗運用の記録を作ります。

実例を動かす

この章では、Web・数学・物理学・ゲームの実装に対してProperty-Based Testing（PBT）を適用します。外部依存は純粋関数・fake・注入可能な時計へ置き換え、何を観測しているかを明示します。

Shell
python -m venv .venv
. .venv/bin/activate
python -m pip install hypothesis pytest
pytest -q

各例は、保証したいこと・なぜ必要か・破れたときの影響をコードの前に置きます。shrinkで得た小さな反例、許容誤差、無効入力、旧スキーマ、seed再現性は「テスト実装の細部」ではなく契約です。

入力範囲を隠さない

NaNを除外したなら、NaNを扱わない仕様だと記録します。generatorのmin/max、許容誤差、操作列の長さをCIログとテスト名に残します。

Web例1：注文シリアライズの往復

保証したいのは、許容された注文をJSONにして戻すと同じ意味になることです。破れると、再読込で金額、ID、ゼロ値、Unicodeが変わります。

Python / Hypothesis
import json
from dataclasses import asdict, dataclass

from hypothesis import given, strategies as st


@dataclass(frozen=True)
class Order:
    id: str
    cents: int


def encode(order: Order) -> str:
    return json.dumps(
        asdict(order),
        separators=(",", ":"),
        sort_keys=True,
    )


def decode(blob: str) -> Order:
    value = json.loads(blob)
    return Order(id=value["id"], cents=value["cents"])


orders = st.builds(
    Order,
    id=st.text(min_size=1, max_size=20),
    cents=st.integers(min_value=0, max_value=10**8),
)


@given(orders)
def test_order_round_trip(order: Order):
    assert decode(encode(order)) == order

ジェネレータは非空IDと非負centsを作ります。未知フィールドを拒否する、欠落フィールドをエラーにする、旧バージョンを読めるといった性質は別の入力戦略へ分けます。

JSONの往復は外部意味の全てではない

日付・Decimal・タイムゾーン・大きな整数・浮動小数には別の表現契約が必要です。Pythonの辞書が等しいだけで、APIのHTTPステータスやDBの型まで保証したことにはなりません。

Web例2：APIバリデーションの境界

limitが1〜100だけ受け入れられることを固定します。上限・下限を明示しないと、ページングが重いクエリや空ページを返します。

Python / Hypothesis
from hypothesis import given, strategies as st


def valid_limit(value: int) -> bool:
    return 1 <= value <= 100


@given(st.integers())
def test_limit_validator_is_exact(value: int):
    assert valid_limit(value) == (1 <= value <= 100)


@given(st.integers(min_value=1, max_value=100))
def test_valid_limit_never_rejected(value: int):
    assert valid_limit(value)


@given(st.one_of(
    st.integers(max_value=0),
    st.integers(min_value=101),
))
def test_invalid_limit_is_rejected(value: int):
    assert not valid_limit(value)

この性質はvalidatorの論理をそのまま再記述しているため、単純な誤りを見つけにくい面もあります。HTTP層・GraphQL resolver・CLIから同じvalidatorが呼ばれることを、観測可能なfakeと統合テストで確認します。

Web例3：認可表と独立モデル

Python / model comparison
from hypothesis import given, strategies as st


roles = st.sampled_from(["guest", "member", "admin"])
actions = st.sampled_from(["read", "write", "delete"])


def model(role: str, action: str) -> bool:
    return (
        role == "admin"
        or (role == "member" and action in {"read", "write"})
        or (role == "guest" and action == "read")
    )


def production(role: str, action: str) -> bool:
    table = {
        ("guest", "read"): True,
        ("member", "read"): True,
        ("member", "write"): True,
    }
    return role == "admin" or table.get((role, action), False)


@given(roles, actions)
def test_authorization_matches_model(role: str, action: str):
    assert production(role, action) == model(role, action)
モデルを同じ辞書から作らない

実装とモデルを同じ定数から生成すると、表の誤りを共有します。仕様レビューで独立に決めた小さなモデルを用意し、全組合せを生成します。

Web例4：レート制限とfake clock

時間を進める操作を生成し、直近60秒の受付数が3件以下であることを検査します。破れると、時計の境界で古い呼び出しが残り、正当なリクエストを拒否したり制限を抜けたりします。

Python / state machine
from hypothesis import strategies as st
from hypothesis.stateful import (
    RuleBasedStateMachine,
    invariant,
    rule,
)


class RateLimitMachine(RuleBasedStateMachine):
    def __init__(self):
        super().__init__()
        self.now = 0
        self.calls: list[int] = []

    @rule(delta=st.integers(min_value=0, max_value=10))
    def advance(self, delta: int):
        self.now += delta
        self.calls = [
            timestamp
            for timestamp in self.calls
            if timestamp > self.now - 60
        ]

    @rule()
    def request(self):
        accepted = len(self.calls) < 3
        if accepted:
            self.calls.append(self.now)
        assert len(self.calls) <= 3

    @invariant()
    def bounded(self):
        assert len(self.calls) <= 3


TestRateLimit = RateLimitMachine.TestCase

このモデルは「受け付けた呼び出し時刻」の集合だけを見ています。本番の分散カウンタ、複数リージョン、時計の後退、永続化失敗は別のfakeやTLA+モデルへ追加します。

数学例1：整数の代数性質

整数加法の可換性・結合性をpropertyにします。これらは集計・差分適用・分割処理のリファクタリングで、順序や括弧を変えてよいことを確認する基礎です。

Python / Hypothesis
from hypothesis import given, strategies as st


@given(st.integers(min_value=-10**6, max_value=10**6),
       st.integers(min_value=-10**6, max_value=10**6))
def test_add_commutative(a: int, b: int):
    assert a + b == b + a


@given(st.integers(), st.integers(), st.integers())
def test_add_associative(a: int, b: int, c: int):
    assert (a + b) + c == a + (b + c)

整数の性質をそのまま浮動小数へ移すと失敗します。固定小数やDecimalなら、桁数・丸めモードを契約にしたpropertyが必要です。

数学例2：浮動小数の誤差境界

Python / Hypothesis
from hypothesis import given, strategies as st


finite = st.floats(
    allow_nan=False,
    allow_infinity=False,
    width=64,
)


@given(finite)
def test_float_identity_has_documented_tolerance(x: float):
    error = abs((x + 1.0) - x - 1.0)
    assert error <= 2.0**-40 or abs(x) > 2.0**40

完全一致ではなく、適用範囲と許容誤差を仕様にします。大きすぎる値を別ケースに分けるなど、なぜその境界を置いたかを説明します。

数学例3：ソートと多重集合

sortの結果をそのまま期待せず、冪等性と長さ保存を分けて検査します。重複数まで保存したいなら集合ではなく多重集合、またはソート済みリストを比較します。

Python / Hypothesis
from hypothesis import given, strategies as st


@given(st.lists(st.integers()))
def test_sorted_is_idempotent_and_length_preserving(xs: list[int]):
    result = sorted(xs)
    assert sorted(result) == result
    assert len(result) == len(xs)


@given(st.sets(st.integers()), st.sets(st.integers()))
def test_union_commutative(a: set[int], b: set[int]):
    assert a | b == b | a

数学例4：Decimalとの比較

Python / Decimal
from decimal import Decimal, localcontext

from hypothesis import given, strategies as st


@given(st.integers(-100_000, 100_000),
       st.integers(-100_000, 100_000))
def test_decimal_add_exact(a: int, b: int):
    with localcontext() as context:
        context.prec = 40
        assert Decimal(a) + Decimal(b) == Decimal(a + b)

別実装をオラクルにする場合、どの丸め規則が違うかを明記します。Decimalを使ったから金融計算が自動的に正しいわけではなく、税・通貨・端数処理の規則をpropertyへ追加します。

物理例1：積分器の一ステップ誤差

単純な調和振動子の一ステップで、エネルギー誤差が小さい範囲に収まることを検査します。これは長時間保存の証明ではなく、dtをどの範囲で使えるかを決めるpropertyです。

Python / Hypothesis
from hypothesis import given, strategies as st


def step(x: float, v: float, dt: float) -> tuple[float, float]:
    return x + v * dt, v - x * dt


def energy(x: float, v: float) -> float:
    return (x * x + v * v) / 2


finite_small = st.floats(
    min_value=-1,
    max_value=1,
    allow_nan=False,
    allow_infinity=False,
)


@given(finite_small, finite_small,
       st.floats(min_value=0, max_value=0.01,
                 allow_nan=False, allow_infinity=False))
def test_energy_error_is_bounded(x: float, v: float, dt: float):
    x2, v2 = step(x, v, dt)
    assert abs(energy(x2, v2) - energy(x, v)) < 0.02

dtを大きくすると反例が出ることがあります。反例は積分器の適用範囲を決める資料であり、テストを弱めて消す理由ではありません。

物理例2：衝突判定の対称性

二つの円の衝突判定は、引数の順番を入れ替えても同じであるべきです。片側だけへ補正を混ぜると対称性が破れ、ゲーム物理の再現性が崩れます。

Python / Hypothesis
from hypothesis import given, strategies as st


def collide(a: tuple[float, float, float],
            b: tuple[float, float, float]) -> bool:
    ax, ay, ar = a
    bx, by, br = b
    distance_squared = (ax - bx)**2 + (ay - by)**2
    return distance_squared <= (ar + br)**2


points = st.tuples(
    st.floats(-100, 100, allow_nan=False, allow_infinity=False),
    st.floats(-100, 100, allow_nan=False, allow_infinity=False),
    st.floats(0, 10, allow_nan=False, allow_infinity=False),
)


@given(points, points)
def test_collision_symmetric(a, b):
    assert collide(a, b) == collide(b, a)

NaNや極端な半径を除外したなら、ゲームエンジンがそれらを受け付けない契約として残します。受け付けるなら、NaNの意味を別のpropertyにします。

物理例3：単位変換の往復

メートルとセンチメートルの変換を浮動小数で往復します。整数なら完全一致を要求できますが、浮動小数では相対誤差と絶対誤差の両方を契約にします。

Python / Hypothesis
from hypothesis import given, strategies as st


def meters_to_cm(value: float) -> float:
    return value * 100


def cm_to_meters(value: float) -> float:
    return value / 100


@given(st.floats(-1e6, 1e6,
                 allow_nan=False, allow_infinity=False))
def test_unit_round_trip(value: float):
    restored = cm_to_meters(meters_to_cm(value))
    tolerance = max(1e-9, abs(value) * 1e-12)
    assert abs(restored - value) <= tolerance

単位変換のpropertyが通っても、秒とメートルを混ぜないことは保証しません。単位を型で分ける、入力の単位を固定する、API名に単位を含めるなど、別の設計も必要です。

ゲーム例1：インベントリ状態機械

addとremoveを操作列で生成し、実装の在庫が簡単なモデルと一致すること、負数にならないことを保証します。破れるとゲーム内通貨やアイテムの複製・不正購入につながります。

Python / state machine
from hypothesis import strategies as st
from hypothesis.stateful import (
    RuleBasedStateMachine,
    invariant,
    rule,
)


class InventoryMachine(RuleBasedStateMachine):
    def __init__(self):
        super().__init__()
        self.model: dict[int, int] = {}
        self.actual: dict[int, int] = {}

    @rule(item=st.integers(0, 5),
          amount=st.integers(0, 3))
    def add(self, item: int, amount: int):
        self.model[item] = self.model.get(item, 0) + amount
        self.actual[item] = self.actual.get(item, 0) + amount

    @rule(item=st.integers(0, 5),
          amount=st.integers(0, 3))
    def remove(self, item: int, amount: int):
        old = self.model.get(item, 0)
        taken = min(old, amount)
        self.model[item] = old - taken
        current = self.actual.get(item, 0)
        self.actual[item] = max(0, current - amount)

    @invariant()
    def agrees(self):
        assert self.actual == self.model


TestInventory = InventoryMachine.TestCase

モデルがremoveのunderflow規則をどう決めたかが重要です。エラーを返す仕様なら、成功・拒否・状態不変を別に観測します。

ゲーム例2：乱数seedの再現性

同じseedと回数なら、独立した乱数生成器が同じ結果を返すことを保証します。グローバルRNGを使うとテストの実行順に依存し、リプレイや不具合調査が不安定になります。

Python / Hypothesis
import random

from hypothesis import given, strategies as st


def roll(seed: int, count: int) -> list[int]:
    rng = random.Random(seed)
    return [rng.randrange(6) + 1 for _ in range(count)]


@given(st.integers(), st.integers(min_value=0, max_value=100))
def test_seed_replays(seed: int, count: int):
    assert roll(seed, count) == roll(seed, count)

同じseedでもゲームルールの版、乱数アルゴリズム、保存形式が変われば再現性が崩れます。seedだけでなく、ルール版と入力を保存します。

ゲーム例3：セーブ・ロード往復

セーブデータをJSON化して戻すと同じ意味になることを検査します。破れると、レベル、コイン、アイテムが消えたり、旧バージョンのセーブを読めなくなったりします。

Python / Hypothesis
import json

from hypothesis import given, strategies as st


states = st.fixed_dictionaries({
    "level": st.integers(0, 100),
    "coins": st.integers(0, 10**6),
    "items": st.lists(
        st.text(min_size=1, max_size=8),
        max_size=10,
    ),
})


def save(state: dict) -> str:
    return json.dumps(state, sort_keys=True)


def load(blob: str) -> dict:
    return json.loads(blob)


@given(states)
def test_save_load(state: dict):
    assert load(save(state)) == state

スキーマ移行を含む場合、旧形式を別generatorで作り、現在のモデルへの変換と保存を分けて検査します。

ゲーム例4：ダメージの単調性

powerを増やしたらダメージが下がらず、armorを増やしたらダメージが増えないことを保証します。破れると、強い装備が弱い装備より不利になるバランス退行が起きます。

Python / Hypothesis
from hypothesis import given, strategies as st


def damage(power: int, armor: int) -> int:
    return max(0, power - armor)


@given(st.integers(0, 1000),
       st.integers(0, 1000),
       st.integers(0, 1000))
def test_damage_monotone_power(p: int, q: int, armor: int):
    if p <= q:
        assert damage(p, armor) <= damage(q, armor)


@given(st.integers(0, 1000),
       st.integers(0, 1000),
       st.integers(0, 1000))
def test_damage_antitone_armor(power: int, a: int, b: int):
    if a <= b:
        assert damage(power, b) <= damage(power, a)

数値の単調性だけでは、クリティカル・属性・丸め・上限を扱えません。ルール変更で性質が変わったときは、テストを削除するのではなく、新しい契約を命名します。

外部依存をfakeで観測する

決済を毎回本当に呼ぶ代わりに、呼び出し回数と引数を観測します。PBTが本番の資格情報やネットワークに依存せず、リトライや失敗を再現できるようになります。

Python / fake dependency
from hypothesis import given, strategies as st


class FakePayment:
    def __init__(self):
        self.calls: list[tuple[str, int]] = []

    def charge(self, key: str, cents: int) -> bool:
        self.calls.append((key, cents))
        return key != "fail"


@given(
    st.text(min_size=1, max_size=10),
    st.integers(min_value=0, max_value=10_000),
)
def test_payment_arguments_are_observable(key: str, cents: int):
    fake = FakePayment()
    fake.charge(key, cents)
    assert fake.calls == [(key, cents)]

失敗を生成するなら、`key == "fail"`のような特殊値だけに依存せず、成功・失敗・タイムアウト・重複応答を表す結果型を作ります。何を再現したfakeかを記録します。

Python / known regression
def test_known_replay_is_stable():
    assert roll(42, 4) == roll(42, 4)
反例から固定例へ

PBTが見つけた入力は、短い回帰テストとして固定します。seedだけを残すのではなく、縮小後の入力、ルール版、性質名を保存します。

領域ごとの境界値

領域最小通常最大不正・特殊
ページサイズ0・120100-1・文字列
ダメージ0501000NaN・負数
在庫010上限負数・重複キー
セッション年齢0TTL内TTLTTL超過・時計後退
セーブデータ空配列通常項目長大欠落・未知schema

境界表はgenerator、APIエラー、監視メトリクスの共通語彙になります。入力範囲を広げるPRでは、どの行を更新したかをレビューします。

失敗運用の流れ
PBTの反例
  -> shrink後の入力を保存
  -> 原因を一文で説明
  -> 回帰テストに固定
  -> 一般化できるpropertyを残す
  -> 必要ならTLA+モデルやLean定理へ反映

まとめ

Webでは往復・認可・バリデーション・時計、数学では代数・ソート・丸め、物理では誤差・対称性・単位、ゲームでは状態機械・seed・保存・単調性を検査しました。

領域ごとにgeneratorを狭く設計し、外部依存はfakeで観測し、許容誤差と特殊値を契約にします。次章では、TLA+の設計反例、Leanの計算核、PBTの実装を一つの購入フローで結びます。

用語集

往復性
encodeしてdecodeするなど、変換の前後で意味が戻る性質。
許容誤差
浮動小数や近似計算で許される差の上限。
fake clock
テストから時間を進められる、注入可能な時計。
モデル比較
簡単な独立モデルと実装の状態・結果を比べる方法。
回帰fixture
過去の失敗入力を固定した再現用のテストデータ。
境界値
最小・最大・空・閾値直前後など、契約が変わる入力。

理解度チェック

問1：JSON往復propertyで、generatorが非負centsだけを作ると何が未検査ですか。
負数が合法か、最大値、未知フィールド、Decimalや日付などの契約です。
問2：物理の一ステップ誤差の反例を消してはいけない理由は何ですか。
積分器の適用範囲やdtの上限を示す設計資料になるためです。
問3：ゲームのseedだけを保存するのが不十分な理由は何ですか。
ルール版・乱数実装・入力が変わると同じseedでも結果が変わるためです。
問4：fake依存で観測すべきものは何ですか。
呼び出し回数、引数、成功・失敗・タイムアウトなど、契約に必要な観測点です。
